The ticket-related models form the core of HelpDesk Pro 2026's data layer. Each Postgrest entity extends `Supabase.Postgrest.Models.BaseModel` and uses Supabase attribute annotations to map C# properties to their corresponding database columns. The view models that accompany them carry `System.ComponentModel.DataAnnotations` attributes to enforce server-side validation before any data reaches the database.

---

## Ticket

The `Ticket` class maps to the `tickets` table in Supabase and is the central entity in the system. It holds scalar foreign keys for all catalog relationships (system, category, priority, risk, state), plus two user references — one for the employee who opened the ticket and one for the support technician assigned to resolve it. Navigation properties are resolved via Postgrest `[Reference]` embeddings at query time.

```csharp
[Table("tickets")]
public class Ticket : BaseModel
{
    [PrimaryKey("ticket_id", false)]
    public long TicketId { get; set; }

    [Column("ticket_code")]
    public string TicketCode { get; set; } = string.Empty;

    [Column("system_id")]
    public int SystemId { get; set; }

    [Column("category_id")]
    public int CategoryId { get; set; }

    [Column("priority_id")]
    public int PriorityId { get; set; }

    [Column("risk_id")]
    public int RiskId { get; set; }

    [Column("state_id")]
    public int StateId { get; set; }

    [Column("subject")]
    public string Subject { get; set; } = string.Empty;

    [Column("description")]
    public string Description { get; set; } = string.Empty;

    [Column("justification")]
    public string? Justification { get; set; }

    [Column("requester_id")]
    public Guid RequesterId { get; set; }

    [Column("assigned_to")]
    public Guid AssignedTo { get; set; }

    [Column("created_at")]
    public DateTime CreatedAt { get; set; }

    [Column("updated_at")]
    public DateTime UpdatedAt { get; set; }

    [Column("attachment_url")]
    public string? AttachmentUrl { get; set; }

    // Navigation properties
    [Reference(typeof(SystemCatalog))]
    public SystemCatalog? System { get; set; }

    [Reference(typeof(Category))]
    public Category? Category { get; set; }

    [Reference(typeof(Priority))]
    public Priority? Priority { get; set; }

    [Reference(typeof(RiskLevel))]
    public RiskLevel? Risk { get; set; }

    [Reference(typeof(TicketState))]
    public TicketState? State { get; set; }

    [Reference(typeof(Usuario), foreignKey: "tickets_requester_id_fkey")]
    public Usuario? Requester { get; set; }

    [Reference(typeof(Usuario), foreignKey: "tickets_assigned_to_fkey")]
    public Usuario? AssignedTech { get; set; }

    [JsonIgnore]
    public List<TicketAttachment> Attachments { get; set; } = new();
}
```

### Scalar Properties

<ResponseField name="TicketId" type="long" required>
  Primary key. Auto-generated by the database — the `false` flag in `[PrimaryKey("ticket_id", false)]` tells Postgrest not to include it in insert payloads.
</ResponseField>

<ResponseField name="TicketCode" type="string" required>
  Human-readable identifier (e.g. `TKT-00042`) generated by the application layer before insert. Maps to column `ticket_code`.
</ResponseField>

<ResponseField name="SystemId" type="int" required>
  Foreign key to `systems.system_id`. Identifies which IT system or product the ticket concerns.
</ResponseField>

<ResponseField name="CategoryId" type="int" required>
  Foreign key to `categories.category_id`. Classifies the type of issue (e.g. Hardware, Software, Network).
</ResponseField>

<ResponseField name="PriorityId" type="int" required>
  Foreign key to `priorities.priority_id`. Drives SLA urgency and UI badge color.
</ResponseField>

<ResponseField name="RiskId" type="int" required>
  Foreign key to `risk_levels.risk_id`. Indicates operational impact if the issue is not resolved promptly.
</ResponseField>

<ResponseField name="StateId" type="int" required>
  Foreign key to `ticket_states.state_id`. Controls the ticket's position in the workflow. Valid values: `1` (PENDIENTE), `2` (EN PROCESO), `3` (EN REVISIÓN), `4` (RESUELTO), `5` (CANCELADO).
</ResponseField>

<ResponseField name="Subject" type="string" required>
  Short title of the issue. Maximum 200 characters. Maps to column `subject`.
</ResponseField>

<ResponseField name="Description" type="string" required>
  Full description of the problem. No length limit enforced at the model layer. Maps to column `description`.
</ResponseField>

<ResponseField name="Justification" type="string | null">
  Optional additional context or business justification provided by the requester. Maps to column `justification`.
</ResponseField>

<ResponseField name="RequesterId" type="Guid" required>
  UUID of the `Usuario` who created the ticket. Maps to column `requester_id`. Corresponds to a `users.user_id` value with role `EMPLEADO`.
</ResponseField>

<ResponseField name="AssignedTo" type="Guid" required>
  UUID of the `Usuario` (SOPORTE technician) currently responsible for the ticket. Populated automatically by the auto-assignment logic in `TicketService`. Maps to column `assigned_to`.
</ResponseField>

<ResponseField name="CreatedAt" type="DateTime" required>
  UTC timestamp set when the ticket row is first inserted. Maps to column `created_at`.
</ResponseField>

<ResponseField name="UpdatedAt" type="DateTime" required>
  UTC timestamp updated on every state change or edit. Maps to column `updated_at`.
</ResponseField>

<ResponseField name="AttachmentUrl" type="string | null">
  Legacy single-file attachment URL. Superseded by the `ticket_attachments` table for multi-file support; retained for backwards compatibility. Maps to column `attachment_url`.
</ResponseField>

### Navigation Properties

<ResponseField name="System" type="SystemCatalog | null">
  Resolved via `[Reference(typeof(SystemCatalog))]`. Populated when querying with Postgrest embedding.
</ResponseField>

<ResponseField name="Category" type="Category | null">
  Resolved via `[Reference(typeof(Category))]`. Provides the category name for display.
</ResponseField>

<ResponseField name="Priority" type="Priority | null">
  Resolved via `[Reference(typeof(Priority))]`. Includes the `Color` hex value used for UI badges.
</ResponseField>

<ResponseField name="Risk" type="RiskLevel | null">
  Resolved via `[Reference(typeof(RiskLevel))]`. Includes the `Color` hex value used for UI badges.
</ResponseField>

<ResponseField name="State" type="TicketState | null">
  Resolved via `[Reference(typeof(TicketState))]`. Exposes the human-readable state name and `OrderNumber` for sorting.
</ResponseField>

<ResponseField name="Requester" type="Usuario | null">
  Resolved via `[Reference(typeof(Usuario), foreignKey: "tickets_requester_id_fkey")]`. The employee who opened the ticket.
</ResponseField>

<ResponseField name="AssignedTech" type="Usuario | null">
  Resolved via `[Reference(typeof(Usuario), foreignKey: "tickets_assigned_to_fkey")]`. The support technician assigned to the ticket. The explicit `foreignKey` parameter is required because `Ticket` has two foreign keys pointing to the same `users` table.
</ResponseField>

<ResponseField name="Attachments" type="List<TicketAttachment>">
  Collection of uploaded files for this ticket. Decorated with `[JsonIgnore]` to prevent Supabase Postgrest from attempting to embed this relation — it is populated manually by `TicketService` in a separate query.
</ResponseField>

## TicketAttachment

The `TicketAttachment` class maps to the `ticket_attachments` table and represents a single file uploaded to the `ticket-files` Supabase Storage bucket. Multiple attachments can be linked to one ticket.

```csharp
[Table("ticket_attachments")]
public class TicketAttachment : BaseModel
{
    [PrimaryKey("attachment_id", false)]
    public long AttachmentId { get; set; }

    [Column("ticket_id")]
    public long TicketId { get; set; }

    [Column("file_name")]
    public string FileName { get; set; } = string.Empty;

    [Column("file_path")]
    public string FilePath { get; set; } = string.Empty;

    [Column("file_url")]
    public string FileUrl { get; set; } = string.Empty;

    [Column("created_at")]
    public DateTime CreatedAt { get; set; }
}
```

<ResponseField name="AttachmentId" type="long" required>
  Auto-generated primary key. Maps to column `attachment_id`.
</ResponseField>

<ResponseField name="TicketId" type="long" required>
  Foreign key back to `tickets.ticket_id`. Maps to column `ticket_id`.
</ResponseField>

<ResponseField name="FileName" type="string" required>
  Original filename as uploaded by the user (e.g. `screenshot.png`). Maps to column `file_name`.
</ResponseField>

<ResponseField name="FilePath" type="string" required>
  Path within the `ticket-files` Supabase Storage bucket (e.g. `42/screenshot.png`). Used to construct download or signed URLs. Maps to column `file_path`.
</ResponseField>

<ResponseField name="FileUrl" type="string" required>
  Full public URL returned by Supabase Storage after upload. Stored for quick retrieval without a round-trip to the Storage API. Maps to column `file_url`.
</ResponseField>

<ResponseField name="CreatedAt" type="DateTime" required>
  UTC timestamp set at insert time. Maps to column `created_at`.
</ResponseField>

## Comment

The `Comment` class maps to the `comments` table. Any authenticated user (EMPLEADO, SOPORTE, or SUPERUSUARIO) can post comments on a ticket. The `User` navigation property is intentionally excluded from Postgrest embedding and is populated manually by `TicketService` to avoid embedding conflicts when the same query also embeds the ticket's `Requester` and `AssignedTech` relations.

```csharp
[Table("comments")]
public class Comment : BaseModel
{
    [PrimaryKey("comment_id", false)]
    public long CommentId { get; set; }

    [Column("ticket_id")]
    public long TicketId { get; set; }

    [Column("user_id")]
    public Guid UserId { get; set; }

    [Column("comment")]
    public string CommentText { get; set; } = string.Empty;

    [Column("created_at")]
    public DateTime CreatedAt { get; set; }

    // Populated manually in TicketService to avoid Postgrest embedding conflicts
    [JsonIgnore]
    public Usuario? User { get; set; }
}
```

<ResponseField name="CommentId" type="long" required>
  Auto-generated primary key. Maps to column `comment_id`.
</ResponseField>

<ResponseField name="TicketId" type="long" required>
  Foreign key to `tickets.ticket_id`. Maps to column `ticket_id`.
</ResponseField>

<ResponseField name="UserId" type="Guid" required>
  UUID of the author. Maps to column `user_id`. Matches a `users.user_id` value.
</ResponseField>

<ResponseField name="CommentText" type="string" required>
  The body of the comment. The C# property is named `CommentText` to avoid a collision with the class name, but it maps to the database column `comment`.
</ResponseField>

<ResponseField name="CreatedAt" type="DateTime" required>
  UTC timestamp set at insert time. Maps to column `created_at`.
</ResponseField>

<ResponseField name="User" type="Usuario | null">
  The author's full user record. Decorated with `[JsonIgnore]` and populated by a separate manual lookup in `TicketService` after the comments list is fetched.
</ResponseField>

## CreateTicketViewModel

`CreateTicketViewModel` is the form model bound to the **Create Ticket** POST action. It carries all fields an EMPLEADO must supply, plus an optional list of file uploads. Validation is enforced by `System.ComponentModel.DataAnnotations` attributes before the controller persists anything to Supabase.

```csharp
public class CreateTicketViewModel
{
    [Required(ErrorMessage = "El sistema es obligatorio.")]
    public int SystemId { get; set; }

    [Required(ErrorMessage = "La categoría es obligatoria.")]
    public int CategoryId { get; set; }

    [Required(ErrorMessage = "La prioridad es obligatoria.")]
    public int PriorityId { get; set; }

    [Required(ErrorMessage = "El nivel de riesgo es obligatorio.")]
    public int RiskId { get; set; }

    [Required(ErrorMessage = "El asunto es obligatorio.")]
    [StringLength(200, ErrorMessage = "El asunto no puede superar los 200 caracteres.")]
    public string Subject { get; set; } = string.Empty;

    [Required(ErrorMessage = "La descripción es obligatoria.")]
    public string Description { get; set; } = string.Empty;

    public string? Justification { get; set; }

    public List<IFormFile>? Attachments { get; set; }
}
```

<ResponseField name="SystemId" type="int" required>
  Selected system. `[Required]` — the form renders a dropdown populated from the `systems` catalog.
</ResponseField>

<ResponseField name="CategoryId" type="int" required>
  Selected category. `[Required]` — dropdown populated from the `categories` catalog.
</ResponseField>

<ResponseField name="PriorityId" type="int" required>
  Selected priority level. `[Required]` — dropdown populated from the `priorities` catalog.
</ResponseField>

<ResponseField name="RiskId" type="int" required>
  Selected risk level. `[Required]` — dropdown populated from the `risk_levels` catalog.
</ResponseField>

<ResponseField name="Subject" type="string" required>
  Ticket title. `[Required]` and `[StringLength(200)]` — must be between 1 and 200 characters.
</ResponseField>

<ResponseField name="Description" type="string" required>
  Full problem description. `[Required]` — rendered as a `<textarea>` in the view.
</ResponseField>

<ResponseField name="Justification" type="string | null">
  Optional business justification. No validation attributes applied.
</ResponseField>

<ResponseField name="Attachments" type="List<IFormFile> | null">
  Zero or more files uploaded via `multipart/form-data`. Each file is saved to the `ticket-files` Supabase Storage bucket and a corresponding `TicketAttachment` row is inserted.
</ResponseField>

## EditTicketViewModel

`EditTicketViewModel` extends the create form with the ticket's identity fields and the existing attachment list. It is used by the EMPLEADO **Edit Ticket** action and gives the user the option to upload additional files or flag existing ones for removal.

```csharp
public class EditTicketViewModel
{
    [Required]
    public long TicketId { get; set; }

    public string TicketCode { get; set; } = string.Empty;

    [Required(ErrorMessage = "El sistema es obligatorio.")]
    public int SystemId { get; set; }

    [Required(ErrorMessage = "La categoría es obligatoria.")]
    public int CategoryId { get; set; }

    [Required(ErrorMessage = "La prioridad es obligatoria.")]
    public int PriorityId { get; set; }

    [Required(ErrorMessage = "El nivel de riesgo es obligatorio.")]
    public int RiskId { get; set; }

    [Required(ErrorMessage = "El asunto es obligatorio.")]
    [StringLength(200, ErrorMessage = "El asunto no puede superar los 200 caracteres.")]
    public string Subject { get; set; } = string.Empty;

    [Required(ErrorMessage = "La descripción es obligatoria.")]
    public string Description { get; set; } = string.Empty;

    public string? Justification { get; set; }

    public List<TicketAttachment> ExistingAttachments { get; set; } = new();
    public List<IFormFile>? NewAttachments { get; set; }

    public bool RemoveAttachment { get; set; }
}
```

<ResponseField name="TicketId" type="long" required>
  The primary key of the ticket being edited. Passed as a hidden form field. `[Required]`.
</ResponseField>

<ResponseField name="TicketCode" type="string" required>
  The read-only human-readable code (e.g. `TKT-00042`). Displayed in the form header but not editable by the user.
</ResponseField>

<ResponseField name="SystemId" type="int" required>
  Same as `CreateTicketViewModel`. Pre-populated from the existing ticket record.
</ResponseField>

<ResponseField name="CategoryId" type="int" required>
  Same as `CreateTicketViewModel`. Pre-populated from the existing ticket record.
</ResponseField>

<ResponseField name="PriorityId" type="int" required>
  Same as `CreateTicketViewModel`. Pre-populated from the existing ticket record.
</ResponseField>

<ResponseField name="RiskId" type="int" required>
  Same as `CreateTicketViewModel`. Pre-populated from the existing ticket record.
</ResponseField>

<ResponseField name="Subject" type="string" required>
  `[Required]` and `[StringLength(200)]`. Pre-populated from the existing ticket record.
</ResponseField>

<ResponseField name="Description" type="string" required>
  `[Required]`. Pre-populated from the existing ticket record.
</ResponseField>

<ResponseField name="Justification" type="string | null">
  Optional. Pre-populated from the existing ticket record.
</ResponseField>

<ResponseField name="ExistingAttachments" type="List<TicketAttachment>">
  The attachments already stored for this ticket, loaded from `ticket_attachments` by the GET action and passed back to the view for display. Not submitted with the form; re-loaded server-side on POST.
</ResponseField>

<ResponseField name="NewAttachments" type="List<IFormFile> | null">
  Additional files the user wants to upload during this edit. Handled identically to `CreateTicketViewModel.Attachments`.
</ResponseField>

<ResponseField name="RemoveAttachment" type="bool">
  A flag available on the view model; individual attachment deletion is handled separately via the `DeleteAttachment` action, which removes a single `TicketAttachment` row from `ticket_attachments` and its corresponding file from Supabase Storage. `UpdateTicketAsync` does not process this field — it is reserved for view-layer use.
</ResponseField>
